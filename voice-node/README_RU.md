# Дополнительный голосовой сервер AIDis (VPS)

Голосовой сервер — это LiveKit на отдельной VPS. Голосовой канал AIDis можно перенести на него:
звонок и стримы этого канала идут через VPS, а не через основной сервер (мини-ПК).

## Что нужно

- VPS с Ubuntu 22.04 или 24.04, публичный IPv4, от 1 ядра и 1 ГБ памяти (лучше 2 ядра / 2 ГБ).
- Поддомен **ровно на один уровень** под доменом вашего AIDis. Ниже в примерах AIDis живёт на `chat.example.com`,
  а голосовой сервер — на `voice2.chat.example.com` (`a.b.chat.example.com` или чужой домен AIDis не примет).
- Открытые у хостера порты (скрипт в конце напишет точный список):
  - 80 и 443 (TCP) — для HTTPS;
  - TCP-порт LiveKit — обычно 7881; если он занят, скрипт возьмёт 7891 или следующий свободный;
  - UDP 50000–60000 — сам звук.

## Установка

1. В DNS создайте A-запись: `voice2.chat.example.com` → IP вашей VPS.
2. Скопируйте `install.sh` на VPS через WinSCP — в домашнюю папку (`/root/` или `/home/<имя>/`).
3. По SSH на VPS:

   ```bash
   cd ~
   sudo bash install.sh --domain voice2.chat.example.com --email ваша@почта.ru
   ```

4. В конце скрипт напечатает три строки (`URL`, `API key`, `API secret`). Вставьте их целиком в AIDis:
   **Настройки → Администрирование → Голосовые серверы → Добавить голосовой сервер** (плюс название, например «Москва»).
5. Там же нажмите серверы (гильдии), которым он доступен: кнопка подсветится, надпись «Пока ни одному серверу» пропадёт.
6. В настройках голосового канала выберите новый сервер в поле «Голосовой сервер». Люди в канале переподключатся сами.

## Если на VPS уже что-то работает

Скрипт сам проверяет порты до запуска:

- **Порты 80/443 свободны** — ставится маленький Caddy, он сам получает сертификат.
- **Порты 80/443 занимает nginx** (на VPS уже есть сайты) — nginx не трогается: в него добавляется сайт
  `voice2.chat.example.com` (файл `/etc/nginx/sites-available/aidis-voice-<домен>`), сертификат выдаёт certbot
  (если его нет — скрипт его поставит). Если сайт для этого домена в nginx уже есть, он остаётся как есть.
- **Порты 80/443 занимает не nginx** (apache, другой контейнер) — скрипт останавливается и пишет, кто их держит.
- **TCP-порт LiveKit занят** (например, на VPS уже есть свой LiveKit) — берётся свободный: 7891, 7901, …
- **UDP-диапазон пересекается с чужим** — скрипт останавливается; выберите другой: `--udp-range 40000-40999`.

Можно задать вручную: `--proxy caddy|nginx`, `--rtc-tcp-port 7891`, `--port 7880` (HTTP LiveKit, только локально),
`--udp-range 50000-60000`.

## Полезное

- Показать три строки ещё раз: `sudo bash install.sh --print`
- Повторный запуск `sudo bash install.sh` (без параметров) обновляет настройки и **сохраняет ключи и выбранные порты**
  (они записаны в `/opt/aidis-voice/install.env`) — в AIDis ничего менять не нужно.
- Логи: `docker compose -f /opt/aidis-voice/docker-compose.yml logs --tail 100`
- Перезапуск: `docker compose -f /opt/aidis-voice/docker-compose.yml restart`
- Удалить: `sudo bash install.sh --uninstall` (сначала удалите сервер в AIDis — его каналы вернутся на основной).
  Сайт в nginx удаляется, только если его создал скрипт; сертификат остаётся.

## Если что-то не так

- **«не отвечает»** в AIDis — откройте `https://voice2.chat.example.com` в браузере (должно быть `OK`) и посмотрите логи.
- **«неверный ключ»** — вставлены не те строки: `sudo bash install.sh --print`, удалите сервер в AIDis и добавьте снова.
- **Сертификат не выдаётся** — A-запись ещё не указывает на VPS или у хостера закрыт порт 80.
- **Подключается, но нет звука** — у хостера закрыт UDP-диапазон (и TCP-порт LiveKit). В окошке качества связи
  (наведите на значок сигнала в звонке, с включённым микрофоном) строка «Транспорт» должна быть `UDP`.
- Если VPS выключится, люди в её каналах отключатся; переключите канал на «Основной»
  или выключите/удалите сервер в AIDis — каналы сами вернутся на основной.
