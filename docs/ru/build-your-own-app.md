# Свои сборки приложения

[К README](../../README.ru.md) · [English](../en/build-your-own-app.md)

Официальное приложение для Windows работает с любым сервером AIDis, поэтому большинству владельцев
это не нужно. Свои сборки имеют смысл, если вы ведёте форк с изменениями в приложении или хотите,
чтобы приложение обновлялось из вашего репозитория.

## 1. Укажите свой репозиторий

В своём форке поправьте `Desktop/desktop.config.json`:

```json
{ "github": { "owner": "your-github-name", "repo": "AIDis" } }
```

и те же имена в `Desktop/package.json` в `build.publish`. Приложение будет обновляться из Releases
этого репозитория. Если указать `owner` равным `OWNER`, приложение соберётся без автообновления.

Если ваши сборки должны ставиться **рядом** с официальным приложением, а не заменять его, поменяйте
ещё `build.appId` в `Desktop/package.json` (например, `io.github.yourname.aidis`) и `APP_ID` в
`Desktop/src/main/config.ts` на то же значение. Потом не меняйте его: от него зависят обновления,
уведомления и автозапуск.

## 2. Сборка

На Windows 10/11 с Node.js 20.19 или новее (лучше 24):

```bash
cd Client
npm ci
cd ../Desktop
npm ci
npm test
npm run desktop:build
```

Результат — в `Desktop/dist`: `AIDis-Setup-<версия>.exe`, `AIDis-Setup-<версия>.exe.blockmap` и
`latest.yml`.

## 3. Публикация

1. Для каждого релиза поднимайте `version` в `Desktop/package.json` (обновление сравнивает версии).
2. На GitHub: **Releases -> Draft a new release**, тег `v<версия>` (например, `v1.0.1`).
3. Приложите три файла из `Desktop/dist` и опубликуйте.

Приложения ваших пользователей найдут релиз в течение часа и предложат обновиться.

## Подпись кода

Неподписанные установщики показывают предупреждение SmartScreen («Система Windows защитила ваш
компьютер»). С сертификатом для подписи кода настройте подпись `build.win` в `Desktop/package.json`,
как описано в документации electron-builder. Предупреждение пропадает, когда у подписанного
приложения накапливается репутация.

## Лицензия

AIDis распространяется под AGPL-3.0. Если вы раздаёте изменённые сборки, опубликуйте изменённый
исходный код под той же лицензией (публичный форк на GitHub это и делает).
