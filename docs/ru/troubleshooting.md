# Решение проблем

[К README](../../README.ru.md) · [English](../en/troubleshooting.md)

Почти всё начинается с журналов. В `/opt/aidis/Server`:

```bash
sudo docker compose ps
sudo docker compose logs --tail 100 backend
sudo docker compose logs --tail 100 livekit
sudo docker compose logs --tail 100 caddy        # только если HTTPS обслуживает Caddy
```

## Установка

| Вы видите | Что делать |
| --- | --- |
| `WARNING: chat.example.com points to 'nothing'` | DNS-записи нет или она ещё не разошлась. Создайте A-запись, подождите, проверьте `getent hosts chat.example.com`, запустите установщик снова. |
| `Ports 80/443 are used by 'apache2' ... not by nginx` | Порты заняты другим веб-сервером. См. [Свой веб-сервер](install.md#свой-веб-сервер). |
| `Ports 80/443 are busy ... Caddy cannot start` | Вы указали `--proxy caddy`, а там работает nginx. Уберите `--proxy` (авто) или укажите `--proxy nginx`. |
| `LiveKit TCP port 17881 is used by 'docker-proxy', using 17891 instead` | Это не ошибка: порт занят другой программой. Откройте новый порт (из итогового вывода) в файрволе хостера. |
| `UDP ports in 50000-50100 are already used` | Здесь уже работает другой голосовой сервер. Запустите снова с `--udp-range 40000-40100`. |
| `nginx already has a site for chat.example.com` | Уберите тот сайт из `/etc/nginx/sites-enabled/` или выделите AIDis другой (под)домен. |
| `certbot failed` | Порт 80 должен быть доступен из интернета, а обе DNS-записи — указывать сюда. Исправьте и запустите установщик снова. |
| `The web client did not build` | Обычно не хватает памяти. Добавьте swap: `sudo fallocate -l 2G /swapfile && sudo chmod 600 /swapfile && sudo mkswap /swapfile && sudo swapon /swapfile` и запустите снова. |
| `https://chat.example.com does not answer yet` | Подождите минуту и откройте снова; проверьте `docker compose ps` и журнал бэкенда. |

## Сайт и приложения

| Вы видите | Что делать |
| --- | --- |
| Браузер пишет, что страница «не отвечает» или долго грузится | Файрвол хостера закрывает 80/443, или контейнеры не запущены (`docker compose ps`). |
| «Настройка AIDis» появляется, хотя вы её прошли | Другой домен или старая вкладка; обновите страницу. Мастер показывается, только пока нет администратора. |
| Код настройки «неверный» | Скопируйте его снова: `sudo cat /opt/aidis/Server/config/setup-code`. |
| Приложение: «По этому адресу открывается сайт, но это не AIDis» | Домен указывает на другой сайт; проверьте DNS и адрес. |
| Приложение: «Сервер не отвечает» | Откройте адрес в браузере на том же ПК. Если там работает — приложение блокирует файрвол на ПК. |
| Регистрации нет на странице входа | Почта ещё не проверена тестовым письмом или режим «Выключена» ([Почта и регистрация](mail-and-registration.md)). |

## Голос

| Вы видите | Что делать |
| --- | --- |
| Пинг «вычисляется» | Нормально, пока вы один и микрофон выключен: измерять нечего. |
| Вход в звонок висит на «подключение» | Нет DNS-записи `rtc.chat.example.com` или LiveKit не запущен (`docker compose ps`; голос включён?). |
| Подключились, но никто никого не слышит | В файрволе хостера закрыты UDP 50000-50100 и TCP 17881. Откройте порты из итогового вывода установщика. |
| Дома работает, а на работе или с мобильного интернета — нет | Откройте UDP 13478 (TURN) в файрволе хостера. |
| Не добавляется дополнительный голосовой сервер | Его домен должен быть поддоменом домена AIDis, а его `https://`-адрес — открываться в браузере. |
| Игра не реагирует на push-to-talk | Игра запущена от администратора: запустите AIDis тоже от администратора. |

## Не помогло

Соберите `docker compose ps`, последние 100 строк журнала бэкенда и описание того, что вы делали, и
создайте issue на GitHub. Уберите домены, IP-адреса и почту, которые не хотите публиковать.
