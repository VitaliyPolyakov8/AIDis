# Обновление

[К README](../../README.ru.md) · [English](../en/updating.md)

## Сервер

```bash
sudo bash /opt/aidis/deploy/update.sh
```

Что он делает, по порядку:

1. **Резервная копия** базы и загруженных файлов в `Server/backups` (пропустить — `--no-backup`, не
   советуем).
2. `git pull` новой версии. Если ничего не изменилось, на этом останавливается (`--rebuild` всё
   равно пересоберёт).
3. Собирает веб-клиент и сервер, пока старая версия продолжает работать.
4. Применяет **миграции базы**. Если миграция не прошла, ничего не перезапускается: работает старая
   версия, а скрипт пишет, как вернуться (коммит и резервную копию для восстановления).
5. Перезапускает с новой версией и ждёт ответа `https://chat.example.com/health`.

Люди увидят короткое переподключение (секунды). Перед большими скачками версий читайте заметки к
релизам на GitHub.

Если `git pull` ругается на локальные изменения, значит, кто-то правил файлы в `/opt/aidis` руками.
Ваши настройки лежат в `Server/.env` и `Server/config/`, которые git не отслеживает, так что обычно
терять нечего: `git -C /opt/aidis status` покажет, что изменилось.

## Изменение настроек

Отредактируйте `/opt/aidis/Server/.env` (каждая настройка описана в `Server/.env.example`), затем:

```bash
cd /opt/aidis/Server && sudo docker compose up -d
```

Чтобы сменить домен, голос или порты, лучше запустите `deploy/setup.sh` снова ([Установка](install.md#повторный-запуск)).

## Версии приложения

Приложения ваших пользователей обновляются сами с GitHub Releases. Файл
`/opt/aidis/Server/config/client-version.json` позволяет ими управлять:

```json
{
  "desktop": {
    "latestVersion": "1.0.0",
    "minimumVersion": "1.0.0",
    "downloadUrl": "",
    "mandatory": false,
    "releaseNotes": [],
    "updateMirrorUrl": ""
  }
}
```

- `minimumVersion`: более старые приложения попросят обновиться до подключения. Поднимайте, когда
  обновлению сервера нужно новое приложение (это будет написано в заметках к релизу).
- `updateMirrorUrl`: `https://`-папка с `latest.yml`, `AIDis-Setup-<версия>.exe` и его `.blockmap` из
  релиза; приложения, подключённые к этому серверу, будут обновляться оттуда, а не с GitHub (полезно,
  если GitHub медленный или недоступен).

Сервер перечитывает файл сам, перезапуск не нужен.
